# MyRoboView 代码评审（2026-09-16 21:40 +08:00）

## 结论

本轮方向正确：Vite 迁移显著简化了依赖与构建链路，双产品输出隔离、产品标识注入、前后端统一安装的职责边界也比上一版清楚。当前实现已达到“本机双产品主链路可运行”，但还不能视为可重复发布：有 2 个 P1 会分别阻断干净检出构建、污染旧版原地升级后的安装目录。

评审基线：`develop@9fe77b58a849`（`[frontend][refactor] merge Vite`）。范围包括 Vite 配置与依赖、CMake 前端编排及安装规则、开发脚本、双产品配置、安装实物、集成测试和 ROS2_DOCS。

## 发现项

### [P1] 私有认证 JSON 被设为必需构建输入，干净检出与 CI 无法提供

- 证据：`roboview/CMakeLists.txt:130-144` 对 `backend/config/auth/*.json` 做 glob，无文件时直接 `FATAL_ERROR`，随后安装进 `etc/web_config`；`.gitignore:1-3` 又明确忽略该目录和 `auth_users.json`。
- 当前本机因为存在被忽略文件而能构建，但仓库和 `.github/workflows/ros2.yml` 没有模板生成、Secret 注入或可选开关。CI 的 checkout 环境与新开发机不具备该前置条件。
- 建议：不要提交真实凭据。认证未启用时让该文件可选；若已经是部署必需项，则提交无秘密 schema/example，并由部署和 CI 以 Secret 生成真实文件。验收必须在干净检出中完成两产品构建。

### [P1] 新安装只清理 hash 子目录，旧布局和异产品资源会残留

- 证据：`roboview/CMakeLists.txt:151-168` 只删除 `etc/web/static`，再把新产物覆盖到 `etc/web`。本机 LRS-X 安装实物仍有 Vite 不再产生的 `asset-manifest.json`、旧 `/robot_urdf` 和旧 `assets/test_map01.png`，同时也存在新 `assets/maps` 与 `assets/robot_urdf`。
- 影响：从 CRA/旧布局原地升级，或复用安装前缀切换产品时，包内仍可能包含废弃文件及另一产品 URDF。后端当前不引用这些旧路径，但制品边界已不再可信，也可能被旧客户端直接访问。
- 建议：定义 `etc/web` 的生成物/持久资源清单，显式移除已废弃路径；测试需先注入旧布局与异产品夹具，再执行安装并对整个 `etc/web` 做允许集合检查，而不只比较 `static/`。

### [P2] URDF 配置 URL 与生产安装 URL 不一致

- 证据：两产品 `robotUrdfConfig.js` 使用 `/robot_urdf/...` 和 `/robot_urdf/`，CMake 与产物检查则把资源安装到 `/assets/robot_urdf/...`。
- 当前 3D viewer 已移除，页面不会请求该 URL，所以不影响现有 Demo；恢复 URDF 展示时会直接 404。
- 建议：统一开发态和生产态 URL，或在服务端提供兼容映射；新增测试读取产品配置并实际请求 URDF 及至少一个 mesh。

### [P2] 产物测试未覆盖本轮最关键的升级安装风险

- 证据：`integration_tests/artifacts.py:25-30` 对 `static/` 做严格集合比较，但没有拒绝 `etc/web` 根目录、旧 `/robot_urdf` 或旧地图文件。两产品测试均通过，而 LRS-X 安装实物仍存在上述残留。
- 建议：增加“旧版 → 新版”和“LRS-X → LRD-W → LRS-X”序列测试，断言允许清单、产品身份、异产品 URDF 缺失，并把结果写入现有 JUnit 与归档。

### [P2] npm stamp 与共享 node_modules 的状态可能分裂

- 每个产品构建目录拥有自己的 `.npm_stamp`，但都写同一个源码树 `node_modules`。并行首次构建可能同时执行 `npm ci`；手工删除 `node_modules` 后 stamp 仍有效，后续只运行 `npm run build` 会失败。
- 建议：至少把 `node_modules` 可用性纳入命令判定并加互斥；若外层体系需要稳定并行构建，改为独立 npm 工作目录/缓存。

## 做得好的部分

- Vite 配置集中承接开发代理、产品环境变量、输出目录和 `static` 布局，前端职责比 CRA 时期清晰。
- `build/<产品>` 避免两个产品的 hash 产物直接互相覆盖，入口页产品 meta 为安装验真提供了稳定锚点。
- 安装规则主动排除开发态 `public/robot_urdf`，再安装当前产品 `asserts`，设计意图正确；地图与 URDF 的新目录也比旧扁平布局更可维护。
- 集成测试已经覆盖产品一致性、robotapp/backend 身份一致性、入口资源存在、DDS/HTTP/WebSocket 主链路，并持久化 JUnit、元数据和分阶段日志。
- Vite 迁移同时移除了未使用的大型依赖，保留 `REACT_APP_` 前缀作为构建接口兼容层，迁移成本控制合理。

## 建议处理顺序

1. 先修复认证配置的来源契约，让干净检出和 CI 可重复构建。
2. 再修复安装迁移清理与完整制品断言，使用旧布局和双产品切换作为回归夹具。
3. 对齐 URDF URL，随后补最小浏览器/Vitest 与 lint 门禁。
4. 最后再处理 npm 并行与缓存健壮性、外层构建体系 CI、NX 交叉编译。
